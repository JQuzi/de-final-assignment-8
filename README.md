# Итоговое задание №8 — PySpark, Airflow и ClickHouse

В этой работе я собрал пайплайн обработки данных о жилых домах. Airflow DAG скачивает исходный CSV, обрабатывает его с помощью PySpark, выполняет расчёты и загружает результат в ClickHouse. Для пунктов 5–7 я также построил графики в Matplotlib.

## Условие задания

Источник: [публичная папка «Список домов РФ»](https://disk.yandex.ru/d/bhf2M8C557AFVw). Требуется:

1. прочитать CSV в PySpark DataFrame и вывести количество строк;
2. проверить формат и отсутствие пустых строк;
3. привести числовые и текстовые поля к корректным типам;
4. вычислить средний и медианный год постройки;
5. найти топ-10 регионов и населённых пунктов по количеству объектов;
6. найти дома с минимальной и максимальной площадью в каждом регионе;
7. посчитать дома по десятилетиям;
8. создать таблицу ClickHouse;
9. подключиться к ClickHouse из Airflow;
10. загрузить обработанный DataFrame;
11. вывести топ-25 домов площадью более 60 м².

Исходный файл я не добавлял в Git. DAG скачивает архив через публичный API Яндекс.Диска, проверяет его контрольную сумму MD5 и распаковывает в Docker volume.

При проверке файла я получил 590 708 строк **вместе с заголовком**. Поэтому после чтения CSV команда `DataFrame.count()` выводит 590 707 объектов. Исходный файл при этом не обрезается, и записи из него не удаляются.

> В условии указано количество этажей, но в скачанном CSV такого столбца нет — вместо него присутствует `population`. Поэтому я оставил фактическую структуру исходного файла.

PySpark запускается в режиме `local[2]` внутри контейнера Airflow. Для файла размером около 347 МБ отдельный Spark-кластер не потребовался.

## Запуск

Требуются Docker Desktop и Docker Compose v2.

```bash
cp .env.example .env
docker compose build
docker compose up airflow-init
docker compose up -d
```

На Windows PowerShell вместо `cp`:

```powershell
Copy-Item .env.example .env
```

Откройте <http://localhost:8081>, войдите с `admin / admin`, включите DAG `houses_final_assignment` и нажмите **Trigger DAG**. В проекте Airflow открывается на порту `8081`, чтобы избежать возможного конфликта со стандартным портом `8080`. Первый запуск скачивает архив около 24 МБ и распаковывает CSV около 347 МБ. При следующих запусках используется локальная копия из Docker volume.

ClickHouse доступен по HTTP на <http://localhost:8123>. По умолчанию база, пользователь и пароль: `analytics`, `airflow`, `airflow`.

## Как устроен DAG

Весь основной процесс находится в файле `dags/houses_pipeline.py` и выполняется в следующем порядке:

1. Сначала DAG скачивает и распаковывает архив, если файла ещё нет в Docker volume.
2. CSV оказался записан в UTF-16LE. Для корректного чтения в Spark я создаю полную рабочую копию в UTF-8. Исходный файл при этом не изменяется.
3. Затем проверяю заголовок, количество строк, пустые записи, некорректные и повторяющиеся ID. CSV читается в режиме `FAILFAST`.
4. Удаляю пробелы-разделители тысяч, например `2 661.10`, и преобразую значения в `Long`, `Integer`, `Double` и `String`. Некорректные числовые значения сохраняются как `NULL`, но сама строка не удаляется.
5. Считаю средний и медианный год постройки, топ-10 регионов и городов, минимальную и максимальную площадь по регионам и количество домов по десятилетиям.
6. По результатам пунктов 5–7 строю три графика Matplotlib. Используется backend `Agg`, поэтому графики можно создавать внутри Docker без графического интерфейса.
7. Перед загрузкой очищаю таблицу `analytics.houses`, чтобы повторный запуск не создавал дубликаты, после чего загружаю в неё обработанный DataFrame партиями.
8. В конце проверяю количество строк в ClickHouse и выполняю SQL-запрос для получения топ-25 домов с площадью больше 60 м².

## Полезные команды

```bash
# Состояние сервисов
docker compose ps

# Логи DAG/scheduler
docker compose logs -f airflow-scheduler

# Проверить количество загруженных строк
docker compose exec clickhouse clickhouse-client \
  --user airflow --password airflow \
  --query "SELECT count() FROM analytics.houses"

# Остановить сервисы, сохранив данные
docker compose down

# Полностью удалить локальные Docker volumes
docker compose down -v
```

## Схема ClickHouse

Для таблицы `analytics.houses` я использовал движок `MergeTree` и сортировку по обязательному полю `house_id`. Числовые поля сделаны nullable там, где в исходных данных встречаются пропуски. Также в таблице сохраняются рассчитанное десятилетие, имя исходного файла и время загрузки.
