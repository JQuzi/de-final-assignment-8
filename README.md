# Итоговое задание №8 — PySpark, Airflow и ClickHouse

Проект скачивает полный набор с публичного Яндекс.Диска, проверяет и преобразует CSV в PySpark, выполняет аналитику, загружает результат в ClickHouse и запускает итоговый SQL-запрос. Все обязательные шаги обработки и работы с БД выполняются одним Airflow DAG.

## Условие задания

Источник: [публичная папка «Список домов РФ»](https://disk.yandex.ru/d/bhf2M8C557AFVw). Требуется:

1. прочитать CSV в PySpark DataFrame и вывести количество строк;
2. проверить формат и отсутствие пустых строк;
3. привести числовые и текстовые поля к корректным типам;
4. вычислить средний и медианный год постройки;
5. найти топ-10 регионов и населённых пунктов по количеству объектов;
6. найти дома с минимальной и максимальной площадью в каждом регионе;
7. посчитать дома по десятилетиям;
8. создать таблицу ClickHouse;
9. подключиться к ClickHouse из Airflow;
10. загрузить обработанный DataFrame;
11. вывести топ-25 домов площадью более 60 м².

Исходный файл не хранится в Git: DAG скачивает архив через публичный API Яндекс.Диска, проверяет MD5 и распаковывает его в Docker volume.

В условии указано 590 708 строк. Проверка полного файла показывает ровно 590 708 физических строк **вместе с заголовком**, поэтому `DataFrame.count()` закономерно выводит 590 707 объектов. Ни одна запись данных не удаляется.

> В тексте задания упомянуто «количество этажей», но фактический CSV содержит колонку `population`. Проект намеренно использует реальный заголовок источника и не переименовывает/не подменяет данные.

## Структура

```text
.
├── dags/
│   └── houses_pipeline.py       # единый DAG: шаги 1–7 и 9–11
├── clickhouse/init/
│   └── 001_create_houses.sql    # схема таблицы (шаг 8)
├── Dockerfile                   # Airflow + Java 17 + PySpark + ClickHouse client
├── docker-compose.yml           # Airflow, PostgreSQL и ClickHouse
├── .env.example
├── .gitignore
└── README.md
```

PySpark работает в `local[2]` непосредственно в контейнере Airflow. Для учебного набора на 347 МБ отдельный Spark-кластер не нужен; при этом обработка действительно выполняется Spark DataFrame API, а не pandas.

## Запуск

Требуются Docker Desktop и Docker Compose v2.

```bash
cp .env.example .env
docker compose build
docker compose up airflow-init
docker compose up -d
```

На Windows PowerShell вместо `cp`:

```powershell
Copy-Item .env.example .env
```

Откройте <http://localhost:8080>, войдите с `admin / admin`, включите DAG `houses_final_assignment` и нажмите **Trigger DAG**. Первый запуск скачивает архив около 24 МБ и распаковывает CSV около 347 МБ. Следующие запуски используют локальную копию в named volume.

ClickHouse доступен по HTTP на <http://localhost:8123>. По умолчанию база, пользователь и пароль: `analytics`, `airflow`, `airflow`.

## Что делает DAG

- определяет фактическую кодировку источника UTF-16LE, сверяет точный заголовок и потоково создаёт полную рабочую копию UTF-8, которую Spark может безопасно делить на партиции; чтение выполняется в режиме `FAILFAST`;
- проверяет 590 708 физических строк и 590 707 записей данных, пустые строки, пустые записи, некорректные и повторяющиеся ID;
- удаляет пробелы-разделители тысяч (`2 661.10`) и приводит поля к `Long`, `Integer`, `Double` и `String`; год принимается только при числовом значении от 1800 до текущего года, а некорректные исходные значения становятся `NULL` без удаления строки;
- считает среднее и медиану через `avg` и `percentile_approx`;
- выполняет агрегации и оконные функции для пунктов 5–7;
- перед повторной загрузкой очищает целевую таблицу, поэтому повторный запуск не создаёт дубликаты;
- загружает DataFrame партиями из Spark partitions и сверяет число строк в ClickHouse;
- выполняет SQL из константы `TOP_25_SQL` и пишет результаты в лог.

Артефакты выполнения находятся внутри volume `houses-data`:

- `/opt/airflow/data/output/analytics.json`;
- `/opt/airflow/data/output/top_25_houses_over_60.json`.

Их также можно посмотреть в логах задачи Airflow.

## Полезные команды

```bash
# Состояние сервисов
docker compose ps

# Логи DAG/scheduler
docker compose logs -f airflow-scheduler

# Проверить количество загруженных строк
docker compose exec clickhouse clickhouse-client \
  --user airflow --password airflow \
  --query "SELECT count() FROM analytics.houses"

# Остановить сервисы, сохранив данные
docker compose down

# Полностью удалить локальные Docker volumes
docker compose down -v
```

## Схема ClickHouse

Таблица `analytics.houses` использует `MergeTree` и сортировку по обязательному `house_id`. Числовые поля nullable там, где источник допускает пропуски; `house_id` обязателен. Дополнительно сохраняются вычисленное десятилетие, имя исходного файла и время загрузки.
